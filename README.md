# SJMTA website

The official South Jersey Music Teachers' Association website at <https://sjmta.org>.

This is a static website: HTML contains the content, CSS controls presentation, and a small JavaScript file enhances the homepage menu. There is no framework, database, backend, or build step. GitHub Pages publishes the files directly from `main` at the repository root.

## Run locally

From the repository root:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Open <http://localhost:8000>. Python 3 is sufficient; Node is not needed to serve the website.

With XAMPP Apache running, the existing checkout is also available at:

<http://localhost/interactive_pages/webpages/sjmta/>

## Find the right file

```text
index.html                 Homepage content, navigation, and upcoming announcements
src/
  pages/                   Standalone information and event pages
  styles/
    home.css               Homepage styles
    pages/                 One clearly named stylesheet for each detail page
  scripts/
    home.js                Mobile menu and header scroll behavior only
assets/
  documents/               Public forms and supporting documents, including past years
  fonts/                   Existing fonts
  ...                      Existing images
scripts/
  check_site.py            Offline link, asset, anchor, and markup checks
  check-browser.mjs        Browser, responsive-layout, and navigation checks
CNAME                      Existing custom domain: sjmta.org
```

| Content               | HTML file                                       | Stylesheet in `src/styles/pages/` |
| --------------------- | ----------------------------------------------- | --------------------------------- |
| About Us              | `src/pages/aboutUs.html`                        | `about.css`                       |
| Our Programs          | `src/pages/ourPrograms.html`                    | `programs.css`                    |
| Calendar of Events    | `src/pages/COE.html`                            | `calendar.css`                    |
| Fall Festival         | `src/pages/fall_festival.html`                  | `fall-festival.css`               |
| Masterclass           | `src/pages/advanced_masterclass.html`           | `masterclass.css`                 |
| Technique Competition | `src/pages/TechniqueCompetitionRepertoire.html` | `technique-competition.css`       |

The existing HTML filenames and document paths are intentional: they preserve published URLs and bookmarks. Stylesheets use descriptive names, even when an older page URL uses an abbreviation. Each page keeps its existing visual theme, so its styles remain independent.

## Update content

1. Edit the relevant HTML page. Content is not generated by JavaScript.
2. For event changes, update the calendar and the event's detail page together. Update the homepage announcement in `index.html` when applicable. Keep each announcement and its link in the same `.event` element.
3. Put new downloads in `assets/documents/`, using a year folder and a descriptive filename for new files. Do not rename or delete published documents without checking existing links. The `2026/` folder includes documents for the 2026–2027 season.
4. From a detail page, a document link starts with `../../assets/documents/`. Its stylesheet starts with `../styles/pages/`. CSS image URLs are relative to the stylesheet, not the HTML.
5. Verify dates, deadlines, fees, venue, contact details, repertoire, and the actual contents of linked forms against the supplied source documents. A filename alone does not establish what a form contains.

Preserve existing section IDs when editing: links such as `JPRA.html#performance-time` depend on them. Add styling in the appropriate CSS file, and use native links/buttons instead of inline JavaScript handlers.

See [maintenance notes](docs/maintenance.md) for existing content questions and the scope of the code cleanup.

## Check changes

The offline checker needs only Python 3.9 or newer:

```sh
python3 scripts/check_site.py
```

Optional development tools use Node.js 22 or newer. They are not required by visitors or GitHub Pages:

```sh
npm ci
npm run check
npm run format:check
npx playwright install chromium
npm run test:browser
```

`npm run format` applies the formatting rules. The browser check starts and stops its own temporary local server, checks every page at desktop and mobile widths, and exercises the menu, keyboard behavior, resizing, scroll header, and navigation without JavaScript. Screenshots are written to the ignored `test-results/` directory. External websites and the Google Maps embed are not tested by these local checks.

To use an existing browser instead of installing Playwright's Chromium, set `BROWSER_EXECUTABLE_PATH`. On macOS with Chrome:

```sh
BROWSER_EXECUTABLE_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" npm run test:browser
```

## Publish

Commit the intended changes, including any new downloadable files, and push to `main`. In GitHub, Pages should remain configured as **Deploy from a branch → main → / (root)**. No generated output directory is needed, and `CNAME` must remain unchanged.

Confirm the new **pages build and deployment** run succeeds in GitHub Actions, then check the live pages and downloads. A successful Git push does not by itself confirm that the live site has deployed. If publishing stalls, an administrator with Pages permissions may need to investigate the build.
